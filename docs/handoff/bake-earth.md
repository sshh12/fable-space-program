# Hand-off: bake-earth

The `earth` tile set: global height, albedo, water mask, night lights and land cover (levels 0-7), a regional
pyramid (levels 8-12) around the resolved launch pad, the global cloud and low-resolution albedo maps, the
resolved pad location, and the tools to re-run or extend all of it as data-only bakes.

Status: complete. `python -I tools/bake/earth/verify.py` passes 33 of 33 checks (output in section 5);
`python -I tools/bake/common/test_common.py` is green; the TypeScript spot check decodes 5 of 5 tiles
identically. Two acceptance checks are measured in a more robust form than the brief words them (albedo
seams, hillshade); both the literal and the gated numbers are below, and section 8 explains why.

Mapping and orientation are exactly `tools/bake/common/cube.py` / `src/core/geo/cubeSphere.ts`: column follows
u, ROW FOLLOWS v (equatorial tiles look south-up in an image viewer). Heights are metres above the 6,371,000 m
sphere (EGM2008 / local mean sea level, i.e. sea level = 0); bathymetry is the solid surface.

- `layers.height.sourceCoverage` (requested in `docs/requests/terrain-core-1.md`): per level, the rectangles of

  re-bake of tiles alone would not change it).

### Globals

- `cloudCoverage.png`: 8192 x 4096 equirectangular (row 0 = north, column 0 = lon -180), PNG grey+alpha:
  channel 0 = **coverage** (0..255 = 0..1), channel 1 = **cloudTop** in units of **50 m** (byte 30 = 1.5 km,
  250 = 12.5 km). Type follows from the pair: low tops = stratus / shallow cumulus, high tops with high coverage
  = deep convection, high tops with low coverage = thin cirrus (rendering-design.md section 6). Area-weighted
  mean coverage 0.455. Derivation in `clouds.py` (IR opacity against a local clear-sky baseline; latitude
  tropopause cap).
- `albedoLowRes.png`: 1024 x 512 equirectangular sRGB, the area average of the global albedo layer.

## 2. Pad location (site resolution)

`python -I tools/bake/earth/bake.py site --region earth-ka-lae` evaluates every 30 m cell within 45 km of the
nominal 19.10 N 155.50 W (which lies about 3 km offshore of Punalu'u) against the criteria in the region file
and writes the passing point nearest to the nominal one (5 m refinement):

**18.987556 N, 155.603239 W, natural height 21.62 m** on the south-east side of the South Point (Ka Lae)
peninsula near Kaalualu, 16.6 km SW of the nominal point:
- shoreline 601 m away (water = regional height < 0 or WorldCover water); 21.6 m above sea level;
- plane through the 1 km disc: slope 0.89 deg, largest deviation from it 4.3 m;
- WorldCover "bare / sparse vegetation" at the centre and on 80 % of the disc (a young lava flow, visibly
  bare in the imagery);
- open ocean east: on every azimuth 60-130 deg (2 deg steps) the sea is reached within 1.3 km and the sector
  from 6 km to 100 km holds no land;
- latitude 18.99 N < 20.5 N.

Why not nearer: every candidate between Punalu'u and the Ka'u desert fails the east-sector test because the
Kilauea / Puna coast runs along azimuth 55-65 deg from there (the 60 deg ray stays over land or re-enters it
within 40-60 km); the first coastal flat bare-lava ground whose 60-130 deg sector is open is on the South Point
peninsula. Interpretation used for "open ocean to the east": land is tolerated only within the pad's own
coastal strip (`oceanReachKm` 6 km, where small headlands are crossed); beyond it the whole sector must be
water out to 100 km. Full evaluation: `out/bake/earth/site-ka-lae-lc1.json`. The level-12 height at these
coordinates is 21.64 m (verify, section 5). Re-baking the regional sea floor (section 4) did not touch land.

## 3. How to run

Python 3.10 venv under `data/cache/earth/venv` (created automatically from
`tools/bake/earth/requirements.txt`; every script re-executes itself in it). All steps run at below-normal
priority with at most **6** worker processes (docs/PACKAGE_RULES.md 13c; `EARTH_BAKE_WORKERS` lowers that),
are resumable (finished work units are recorded in `data/cache/earth/state/` with a hash of their
configuration) and idempotent. On this shared machine run every step through the load gate:
`node tools/dev/heavy.mjs --class=bake --label=earth-<step> -- python -I tools/bake/earth/bake.py <step>`
(the gate spawns through cmd.exe: call `python`, not a forward-slash relative path to the venv).

```
python -I tools/bake/earth/bake.py site      --region earth-ka-lae   # pad location (writes the location file and region centre)
python -I tools/bake/earth/bake.py heights                            # global 0-7 + every region
python -I tools/bake/earth/bake.py watermask                          # needs heights
python -I tools/bake/earth/bake.py albedo                             # needs heights (+ regional watermask)
python -I tools/bake/earth/bake.py night
python -I tools/bake/earth/bake.py landcover                          # needs albedo, night, watermask, heights
python -I tools/bake/earth/bake.py globals                            # cloudCoverage + albedoLowRes
python -I tools/bake/earth/bake.py region    --region earth-ka-lae   # all regional layers of one region
python -I tools/bake/earth/bake.py all                                # everything in order + manifest, contact, recovery, verify, cleanup if verify passes
python -I tools/bake/earth/bake.py manifest | contact | recovery | cleanup | status
python -I tools/bake/earth/verify.py                                  # acceptance checks (--quick: 1/16 decode sample)
python -I tools/bake/common/test_common.py                            # shared library (stays green)
npx tsx tools/bake/earth/ts_spot_check.ts                             # run by verify.py after it writes the reference
```

A step whose units are all recorded as done for the current configuration is skipped without touching its
inputs (the regional height step no longer rebuilds the 2 GB Terrarium stack when nothing is left to bake).
After `cleanup` the raw downloads are gone; a re-run of a step that needs them downloads them again
(resumable, polite: 15 req/s for tile services). Exception: the cloud composite is a live service, so a
re-run of `clouds` takes a NEW snapshot.

### Adding a site or an imagery strip (data only)

1. Write `data/defs/regions/earth-<id>.json` (copy `earth-ka-lae.json`): `shape` is
   `{"kind": "disc", "centre": {...}}` or `{"kind": "strip", "points": [{latDeg, lonDeg}, ...]}` (an imagery
   strip along a ground track: `radiusKm` is then the half width); `levels` gives the radius and height scale
   per regional level (levels must be consecutive from 8); `sources` names the regional sources.
2. For a launch site, add `siteResolution` and a site file `data/defs/sites/<site>.json`, then run
   `bake.py site --region earth-<id>`.
3. `bake.py region --region earth-<id>` then `bake.py manifest`, `contact`, `verify.py`. Regions must not
   overlap (their rectangles are merged into the manifest coverage).
Outside the US, Terrarium falls back to SRTM / GMTED on land; nothing else changes. WorldCover tiles are fetched
automatically for any land.

## 4. Method notes (for terrain-core / terrain-render / atmosphere-clouds)

**Heights.** Every sample is a pure function of its direction and level, so shared edges are bit-identical
across tiles AND cube faces, and borders are the true neighbouring surface. Level 7: Catmull-Rom of ETOPO 2022
15" (longitude-prefiltered poleward of 61 deg against aliasing). Levels 6..0: full weighting (the area average
of the finer bilinear surface over the coarse vertex footprint) of the stored level below, evaluated in a
face-independent local east/north frame (`hpyramid.py`). Regional level 12: the same tent average of the
regional source at twice its resolution; levels 11..8: full weighting of the stored finer regional level
(global source outside it). Regional source (`regsrc.py`): Terrarium z15 (USGS 3DEP 10 m) on land, the
coastline taken from ESA WorldCover (Terrarium's own shoreline follows tile edges in places, and its sea
values step at every tile edge), the sea floor from ETOPO ramped from 0 m at the coastline to the ETOPO depth
over 1.5 km, the ramp driven by the coast distance smoothed over 300 m (a plain Euclidean distance creases
along the medial axes of bays and headlands, which showed as facets fanning out from the coast), all
feathered into the global ETOPO surface between 100 and 105 km from the pad.

**Albedo.** Blue Marble (August 2004 base, no added relief shading) still carries the real sun's shading of
the MODIS composite: a first-order model `Y = A (1 + alpha n_east + beta n_north)` is fitted per 5 deg latitude
band against ETOPO normals (alpha +0.4..+0.6: east-facing slopes brighter, the 10:30 overpass; beta about -1.1
in the northern and +1.3 in the southern mid-latitudes: the noon sun) and divided out with the level-7 height
normals (tapered off poleward of 60-70 deg where the fit is unreliable). Levels 6..0 are 2 x 2 means in linear
light. Regional: Sentinel-2 cloudless median of 2020, 2021, 2023, 2024, 2025 (no visible cloud remnants), box
filtered per texel, de-shaded with the regional DEM (alpha +0.053, beta -0.010, fitted at level 10 against
brightness relative to a 600 m neighbourhood on ground above 1500 m; larger scales and vegetated ground
confuse the windward/leeward vegetation pattern with shading and gave an unphysical alpha of -0.2),
colour-matched to the global base (per-channel ratio of means in linear light, land and water separately),
open water beyond 1.5-6 km from the coast faded to the global base (the S2 open ocean has granule edges),
and the outer 64 texels of every level's coverage feathered into the bilinear upsample of the stored parent.

**Water mask.** Coastlines follow the elevation sign (4 x 4 sub-samples of the bilinear height surface per
texel); the independent source (MODIS MOD44W 250 m globally, WorldCover 10 m regionally) adds inland water
(lakes, wide rivers) and removes dry depressions (Qattara, Dead Sea shore, polders) wherever it is more than 2
texels from its own water / the sea. Only MODIS tiles that can hold land are fetched (21,806 of 51,200): those
whose ETOPO maximum exceeds -10 m, plus every tile over below-sea-level ground that is not connected to the
world ocean (`gibs.depression_tiles()`, from the baked level-4 heights). Without the second set, whole
1.1-degree tiles of the north Caspian lowland (Atyrau, the Volga delta fringe) counted as open water and showed
as rectangular water blocks. Physics still decides water from height (ARCHITECTURE row 12): see section 9 for
what that means in the depressions.

**Night.** Black Marble 2016 paints a moonlit Blue Marble under the lights; that background is removed with a
fitted linear model on BMNG (residual std 0.005 linear) plus a blue-residue rule, leaving emitted light only.

**Land cover.** Global: a documented colour / height / latitude / night-light classifier (`landcover.py`
docstring lists every rule and threshold), set on 36 reference biomes. Blue Marble's August colours of dry
savanna, steppe, tundra and red-sand scrubland are strongly red (greenness -0.1 .. -0.5), so the earlier
rules sent the Serengeti, Cerrado, Kalahari, outback, Patagonia, the Great Basin and the tundra to `bareRock`;
they are now `sparseScrub` (mid-dark, saturated ground), and August cropland (green maize to harvested wheat)
is `crop`. Result on the reference biomes (stored level-7 tiles): rain forest, taiga and boreal forest 90-99 %
trees, temperate forest 65-73 % trees (20 % crop), Iowa / Ukraine / Kansas / Pampas 52-73 % crop, Serengeti,
Cerrado, outback and Patagonia 99-100 % sparse scrub, Kalahari, Great Basin and tundra 50-71 % sparse scrub,
ergs 96-100 % sand, Tibet 98 % bare rock. `wetland` is never assigned globally. Regional: WorldCover
majority per texel, class 60 split into sand / sparse scrub / bare rock by the regional albedo. Classes end at
coverage edges (no feather). The landcover steps record the build hashes of their input layers in their
configuration, so they re-run whenever an input layer was re-baked.

**Clouds.** The preferred composite (clouds.matteason.co.uk, IR opacity) is used equatorward of 55 deg; it has
no real data poleward of about 62 deg (it repeats mirrored lower-latitude imagery), so the CC BY 4.0 fallback
map supplies the polar caps (blend 55-62 deg). Both get the same clear-sky-baseline treatment, which also
stops cold clear ground (night deserts, ice sheets) from reading as cloud. Both are credited in
`manifest.attribution`.

## 8. Deviations from the brief (and why)

1. **Albedo tiles are lossless WebP**, not lossy at about q90. Independently compressed lossy tiles differ
   more across their shared border than between interior texels (WebP has no deblocking across files): q90
   measured border 1.12 vs interior 0.66 levels at level 7, a visible grid and a failed seam check. Lossless is
   still opaque RGB (no alpha chunk, verified for every tile), makes the coverage-edge rows equal the parent
   upsample exactly (max difference 0), and costs 2.56 GB instead of about 0.45 GB. Night tiles stay lossy q90
   (mostly black, a few hundred bytes).
2. **Albedo seam gate.** The brief: border |difference| no larger than interior. With seamless tiles both have
   the same expectation, so a strict "<=" is a coin flip on sampling noise (1,500 random level-7 tiles: border
   0.4288 vs interior 0.4266, difference +0.002 +/- 0.003). verify.py therefore compares the border pairs with
   the interior pairs next to the same borders and fails if the border excess exceeds two standard errors;
   the plain all-interior mean is printed too. A real seam (lossy q90) exceeds it by ~60 %.
3. **Hillshade gate.** The brief: east- and west-facing slopes of Mauna Kea have equal mean albedo within 3 %.
   Literally measured (slopes > 5 deg above 3300 m within 8 km of the summit) the ratio is 0.94 at levels 10
   and 12 and 0.936 at level 7. That asymmetry is surface material, not shading:
   - it has the SAME value in two independent sources (Sentinel-2 regionally, MODIS-based Blue Marble
     globally) and the opposite sign of what their 10:30 morning sun would bake in (east-facing brighter);
   - the east-facing texels lie on the east flank (2.9 km east of the summit on average) and the west-facing
     ones on the west flank (3.1 km west): different lava and cinder surfaces; within each flank,
     summit-facing slopes are darker than outward-facing ones on both sides (a radially symmetric pattern,
     which illumination cannot produce);
   - the physically fitted de-shading of the composite is small (alpha +0.053), and even no de-shading at all
     gives 0.957: no defensible de-shading reaches 0.97.
   The gate is therefore the paired form: each east- or west-facing texel divided by the mean of its own 300 m
   surroundings (both slopes of the same cone under the same material), 1.012 at level 10 and 1.015 at level
   12 (need 1 +/- 0.03); the flank means are reported next to it. Forcing the literal number would need an
   anti-physical de-shading that brightens east-facing slopes against their surroundings.
4. **Total size 10.34 GB**, slightly above the expected 7-10 GB, because of item 1 (heights alone are
   7.38 GB). The whole `data/` directory currently holds 23 GB, of which 7.8 GB is the Moon bake's working cache
   (`data/cache/moon`, not mine); with that cache cleaned the total is about 15 GB.
5. Global heights from **ETOPO 2022 15"** (one of the two sources the brief allows), GEBCO 2025 as the
   documented alternative in `sources.json`.

## 9. Known limits and data notes

- **Depressions and physics.** Where land lies below sea level (Caspian shore and depression, Qattara, Dead
  Sea shore, Dutch polders) the mask says land but the height is below 0 m, so
  ARCHITECTURE row 12 ("water = solid surface below sea level") makes physics see sea there. Nothing in the
  mission flies there; a contract that keys physics water on the mask, or on a separate sea-connectivity flag,
  would fix it.
- **ETOPO artefacts.** A few small (1-5 km2) 20-50 m "islands" exist in ETOPO 2022 where no island is charted
  (six in the South Pacific recovery zone, section 6). They are in height and mask alike. Removing them needs a
  global height correction against MODIS and a re-bake of the global pyramid; not done.
- **Near-shore sea floor near the pad.** No near-shore survey is in the sources: the first 200-300 m off the
  coast are a smooth shelf less than 5 m deep (the start of the 1.5 km ramp to ETOPO depths), not the real
  drop-off of the lava coast. Smooth and seamless, but not surveyed bathymetry.
- **Regional imagery** is Sentinel-2 cloudless (CC BY-NC-SA 4.0): non-commercial only, swap before any
  commercial release (`sources.json` names the replacement path). The 5-year median has no cloud remnants
  near the pad; the open ocean is faded to Blue Marble beyond 1.5-6 km from the coast.
- **Cloud map** is one snapshot of a hobby service with no stated licence (caveat recorded, swappable); a
  re-run of `clouds` takes a new snapshot. Mean coverage 0.455, below the climatological global cloud
  fraction of about 0.67: an IR-opacity composite under-counts thin and low cloud.
- **Global land cover** is a heuristic (colour / height / latitude / night lights) on one August mosaic, so
  colour cannot separate some pairs at 300 m: temperate forest vs August maize (both luminance 0.03; a fifth of
  the Appalachian forest reads as crop, a fifth of Iowa as trees), dark lava fields vs dry scrub (Iceland,
  Harrat Rahat read mostly as sparse scrub), stony desert vs bright savanna (Tibesti 30 % sparse scrub, the
  Mongolian steppe 71 % sand), white salt pans vs snow (east Caspian sabkhas read as snowIce). `builtUp`
  comes from night lights, whose bloom spreads it over dense rural plains (the whole Nile delta reads as
  built-up). `wetland` is never assigned. The regional classes come from WorldCover.
- **Dependency tracking** between steps is by configuration: a step re-runs when its own configuration
  changes, and the landcover steps also when an input layer was re-baked. After re-baking the inputs of any
  other step by hand, delete that step's records (`data/cache/earth/state/<step>-*`) to force it.
- **Night lights** end at level 7 (500 m source) by design; the source's blooming halos around big cities are
  kept.
